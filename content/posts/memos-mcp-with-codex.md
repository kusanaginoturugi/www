日々のメモを AI から検索・追記できるようにすると、過去の作業記録を使い直しやすくなります。

今回、セルフホストしている [Memos](https://usememos.com/) を Codex の MCP として接続しました。Memos には MCP サーバーが内蔵されているため、別途ブリッジ用のプログラムを作る必要はありません。

## できること

MCP を接続すると、Codex から次のような操作ができます。

- メモ一覧の取得
- キーワードによるメモ検索
- 個別メモの取得
- 新しいメモの作成・更新
- タグ、添付ファイル、コメントの取得

たとえば「前回このサーバで何を変更したか」「この顧客の打ち合わせメモはどこか」といった情報を、作業中に探せます。作業の終わりに手順や判断をメモとして残す運用にも使えます。

## Memos 側で PAT を作る

Memos にログインし、`Settings` → `My Account` → `Access Tokens` から Codex 用の Personal Access Token (PAT) を作成します。

PAT はパスワードと同じ扱いです。チャットや Git リポジトリに書かず、端末の環境変数で管理します。

```sh
export MEMOS_PAT="作成したPAT"
```

シェルを開き直しても使うなら、利用しているシェルの設定ファイルに安全に設定するか、パスワードマネージャーや秘密情報管理の仕組みから読み込むようにします。

## Codex に MCP を追加する

Memos の MCP エンドポイントは通常 `/mcp` です。次のコマンドで HTTP MCP として登録できます。

```sh
codex mcp add memos \
  --url https://memos.example.com/mcp \
  --bearer-token-env-var MEMOS_PAT
```

`memos.example.com` は、自分の Memos のホスト名に置き換えます。登録後は Codex を再起動し、次のコマンドで確認します。

```sh
codex mcp list
```

`memos` が `enabled` と表示され、Bearer token の環境変数が `MEMOS_PAT` になっていれば接続設定は完了です。

## 最初に決めておく運用ルール

MCP は読み取りだけでなく書き込みもできます。便利な反面、保存先が仕事の記録ならルールを先に決めた方が安全です。

- 削除は明示的に依頼したときだけ実行する
- 作成するメモには作業日とタグを付ける
- 顧客情報や認証情報を含むメモの扱いを決める
- AI が作った記録は、必要なら人が見直してから共有する

まずは検索・取得・作成の3つから使い始めると、既存のメモ資産を壊さずに運用へ組み込めます。

## 自分の記録を作業に戻す

Memos を単なるメモ置き場で終わらせず、作業環境から呼び出せる状態にすると、記録を残す意味が変わります。

構成情報、障害対応、打ち合わせ、デプロイ手順などを Memos に残しておけば、次回の作業時に検索して再利用できます。小さなチームや個人事業でも、作業が属人的になりすぎないための土台になります。
